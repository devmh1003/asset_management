# 자산관리 플랫폼

개인 자산현황 엑셀(`B.S / D.L / C.F / Main / 포폴구성 / 결산` 시트)의 구조를 웹으로 옮긴 HTML 기반 자산관리 앱입니다.
Firebase(Auth + Firestore) 에 저장하고, 엑셀로 내려받아 편집한 뒤 다시 업로드할 수 있습니다.

- 배포: https://devmh1003.github.io/asset_management/
- Firebase 프로젝트: `asset-management-6c342` (Spark 무료 플랜, Firestore `asia-northeast3`)

### 여러 사용자 이용

- 누구나 Google 또는 이메일로 가입해 자기 계정의 데이터만 사용합니다. 첫 로그인 시 표시 이름·출생연도·시작 방식(기본 항목/빈 상태)을 묻습니다.
- 기본 항목은 일반 템플릿(주거래 통장·파킹통장·증권·ISA·연금저축·IRP·대출 등, 금액 0)으로 생성됩니다.
- 로그인 화면에 개인정보 처리 안내(저장 항목·위치·관리자 열람 가능성·변경 이력·AI 전송 범위·탈퇴)를 제공합니다.
- 관리자가 **가입 승인제**를 켜면 새 계정은 승인 전까지 “승인 대기” 화면만 보이고 Firestore 쓰기가 거부됩니다.
- **변경 이력**: 로그인·가입, 항목 추가/수정(필드별 이전 → 이후 값, 4초 단위로 묶음)/삭제, 엑셀·JSON 가져오기, 일괄 작업, 내보내기, 관리자 작업이 `auditLogs` 에 서버 시각으로 기록됩니다. 사용자는 수정할 수 없고 본인 기록만 볼 수 있습니다.

### OpenAI 연동 방식

- 설정 페이지에서 **본인 OpenAI API 키**를 입력합니다. 키는 브라우저 `localStorage` 에만 저장되고 Firestore 등 서버로는 전송되지 않습니다 (공용 PC 에서는 사용 후 삭제).
- 질문 시 자산·부채·현금흐름·KPI 의 **요약(이름·금액·분류·비율, 억원 단위)** 과 건강 점수·알림이 시스템 프롬프트로 함께 전송됩니다. 이메일 등 개인 식별 정보는 포함하지 않습니다. “데이터 요약 보기” 로 전송 내용을 확인할 수 있습니다.
- 기본 모델 `gpt-4o-mini` (질문 1회 ≈ 1~3원). 모델명은 자유 입력.
- 키를 브라우저에 두고 싶지 않다면 `엔드포인트` 를 자체 프록시(Cloudflare Worker 등, OpenAI 호환 `/chat/completions`)로 바꾸고 키를 비워 두면 됩니다.
- AI 답변은 참고 정보이며 투자 권유가 아닙니다.

## 엑셀처럼 쓰기

- 헤더 클릭 정렬, `Enter`/`↑`/`↓` 로 같은 열의 위·아래 행 이동, 행 순서 이동(↑↓)·복제·삭제
- 검색 필터, 대분류별 자동 색상, 원화환산 데이터바, 음수 빨간색
- 금액 칸에 `1.2억`, `500만`, `1,200만원`, `$1,000` 처럼 입력하면 원 단위로 파싱 (통화 기호가 있으면 통화도 자동 설정)
- 소분류 이름을 입력하면 키워드로 대분류/중분류 자동 분류 (예: `업비트` → 가상자산 › 거래소 현물, `청약` → 현금 › 청약저축). 분류가 기본값일 때만 적용되며 언제든 수정 가능
- 표가 길면 페이지로 나뉩니다 (기본 50행, 20/50/100행·전체 보기 선택). 합계는 항상 전체 행 기준이며, 새 항목을 추가하면 그 행이 있는 페이지로 이동합니다
- 소분류·운용위임사 자동완성, `✨ 자동 정리` 버튼(공백 정리·미분류 자동 분류·통화 보정), 중복 이름 경고

## 실행

정적 파일이므로 `public/` 폴더를 아무 웹서버로 띄우면 됩니다.

```bash
python dev/serve.py 8765
```

- `public/js/firebase-config.js` 의 `apiKey` 가 비어 있으면 **로컬 모드**(브라우저 localStorage 저장)로 동작합니다.
- URL 에 `?local=1` 을 붙이면 Firebase 설정이 있어도 로컬 모드로 열립니다 (로그인 없이 테스트).
- `npx firebase-tools emulators:start --only auth,firestore` 로 에뮬레이터(Auth 9199, Firestore 8089, Java 11+ 필요)를 띄우고 `http://localhost:8765/?emu=1` 로 열면 실제 규칙으로 여러 계정을 시험할 수 있습니다 (localhost 에서만 동작).

## Firebase 설정 (무료 Spark 플랜)

1. [Firebase 콘솔](https://console.firebase.google.com) 에서 프로젝트 생성
2. **Authentication → Sign-in method** 에서 `Google` 과 `이메일/비밀번호` 사용 설정
3. **Firestore Database** 생성 (프로덕션 모드, 리전 `asia-northeast3` 권장)
4. Firestore **규칙** 탭에 `firestore.rules` 내용 붙여넣기
5. **프로젝트 설정 → 내 앱 → 웹 앱 추가** 후 `firebaseConfig` 값을 `public/js/firebase-config.js` 에 복사
6. **Authentication → Settings → 승인된 도메인** 에 배포 도메인(예: `devmh1003.github.io`) 추가

### 보안 모델

- 웹 `apiKey` 는 공개 식별자입니다. 접근 제어는 `firestore.rules` 와 승인된 도메인이 담당합니다.
- 각 사용자는 `users/{자기 uid}` 아래만 읽고 씁니다.
- 관리자: `firestore.rules` 의 부트스트랩 이메일 목록 또는 `admins/{email}` 문서. 관리자는 모든 사용자 데이터 열람·정리, `profiles` 의 `disabled` 설정, 추천 분류 템플릿(`meta/taxonomyTemplate`) 편집 가능.
- 관리자 판별은 규칙·앱 모두 **이메일 인증된** 계정만 인정합니다.
- 비활성화(`disabled`)·승인 대기(`pending`) 계정은 로그인은 되지만 Firestore 쓰기가 거부됩니다 (앱에서도 읽기 전용). 사용자는 자신의 `disabled`·`pending`·`approvedAt`·`approvedBy` 를 바꿀 수 없고, 승인제가 켜진 동안 새 프로필은 `pending: true` 로만 만들 수 있습니다.
- 프로필은 정해진 필드만 저장할 수 있고, `emailVerified` 는 실제로 인증된 토큰일 때만 `true` 로 기록됩니다. 관리자 화면에 "이메일 미인증" 이 표시되며 승인 시 경고합니다 (다른 사람 이메일 사칭 방지).
- 관리자 메모는 대상 사용자가 읽을 수 없는 `adminNotes/{uid}` 에 저장합니다.
- `users/{uid}` 아래에는 앱이 쓰는 컬렉션(`meta` 는 `settings` 문서만)에만 쓸 수 있습니다.
- 관리자 열람 모드는 앱과 저장소 계층 모두에서 쓰기를 막고, AI 기능(외부 전송)도 막습니다. 열람·승인·메모 등 관리자 작업은 열람 중에도 이력에 남습니다.
- `auditLogs` 는 본인 uid·이메일과 서버 시각(`request.time`)으로만 추가할 수 있고 수정은 불가, 삭제는 기본 관리자(소유자)만 가능합니다.
- 로그아웃하면 페이지를 새로 불러와 이전 사용자의 데이터가 메모리에 남지 않습니다. OpenAI 키와 AI 대화는 브라우저에 **계정별로** 따로 저장됩니다.
- `index.html` 의 Content-Security-Policy 로 스크립트는 자기 사이트·고정 버전 CDN·Firebase·Google 로그인에서만 실행되며, SheetJS·Chart.js·폰트 CSS 는 SRI 해시로 변조를 검사합니다.
- `meta/appConfig`(공지·가입 정책)·`meta/taxonomyTemplate` 은 로그인 사용자 읽기, 관리자만 쓰기입니다.
- 사용자는 설정에서 비밀번호 재설정 메일·회원 탈퇴(데이터·프로필·인증 계정 삭제, 최근 로그인 필요)를 직접 할 수 있습니다. 다른 사용자의 인증 계정 삭제는 Firebase 콘솔에서만 가능합니다 (무료 플랜에는 서버 코드가 없음).

## 배포

`main` 브랜치에 푸시하면 GitHub Actions 가 `public/` 을 GitHub Pages 로 배포합니다.

## 엑셀 입출력

- **다운로드**: 상단 `⬇ 전체 엑셀` 은 모든 시트를 한 파일로, `⬇ 이 페이지` 는 지금 보는 페이지의 시트만(예: 자산, 소비내역, KPI·관리목표) 내보냅니다. 페이지별 파일도 그대로 다시 업로드할 수 있으며 그 시트만 바뀝니다. 헤더에 `*` 가 붙은 열은 자동 계산 열입니다.
- **업로드**: 같은 양식의 파일을 올리면 시트별 행 수를 확인한 뒤 **교체**(파일 기준으로 전부 바꿈) 또는 **병합**(ID 기준 추가/수정) 을 선택합니다.
- **빈 양식 다운로드**: 금액이 0 인 기본 구조 파일을 받습니다.
- 시트: 자산(B.S) · 부채(D.L) · 부동산 · 현금흐름(C.F) · 연도별추이 · 포트폴리오 · KPI · 시나리오 · AI리포트 · 소비내역 · 관리목표 · 환율 · 분류체계 · 안내
- **소비내역**: 소비내역 페이지의 “명세 가져오기” 는 카드사/은행에서 내려받은 임의 양식의 이용내역을 받습니다 (헤더에서 날짜·금액·내용·입금·결제수단 열을 자동 추정, 날짜+내용+금액이 같은 거래는 중복 제외). “소비내역 다운로드” 는 소비내역만 단독 파일로 내려받으며 같은 양식으로 다시 올릴 수 있습니다.
- **JSON 전체 백업/복원** 도 설정 페이지에서 가능합니다.

## 데이터 구조 (Firestore)

```
users/{uid}/assets/{id}       기준일(basis), 대분류, 중분류, 소분류, 통화, 공정가치, 기대이익률, 연보수율(fee), 운용위임사, 기타
users/{uid}/liabilities/{id}  채권자, 금액, 만기일, 금리, 상환방식 (reId: 부동산 보증금 연동)
users/{uid}/realestate/{id}   명칭, 유형, 용도, 주소, 면적, 지분(share), 취득일/취득가/부대비용, 시세(value)·시세이력(valuations), 담보대출(loanId), 받은 보증금, 월세, 연 보유비용
users/{uid}/cashflow/{id}     연도, 구분(수입/지출), 그룹, 항목, 월예산(budget, 만원), m[12] (만원)
users/{uid}/reports/{id}      AI 리포트 (날짜, 제목, 모델, 내용)
users/{uid}/transactions/{id} 소비내역 (날짜, 구분, 내용, 카테고리, 금액, 결제수단, 메모)
users/{uid}/history/{id}      기준일, 평가, 순자산, 부채비율, 목표치, 나이
users/{uid}/portfolio/{id}    안 이름, 구분, 대분류, 중분류, 형태, 금액, 최대/최소/평균 수익률
users/{uid}/kpis/{id}         연도, KPI명, 지표, 방향, 목표, q[4](수동 실적), 메모
users/{uid}/scenarios/{id}    시뮬레이션 저장본
users/{uid}/goals/{id}        항목, 목표, 지표, 현 상황, 전략, 진행
users/{uid}/meta/settings     환율(fx, fxUpdatedAt, fxAuto), 분류체계(taxonomy), 출생연도(birthYear)
profiles/{uid}                이메일, 이메일 인증 여부, 이름, 가입/최근 로그인, 로그인 횟수, disabled, pending, 승인자
adminNotes/{uid}              관리자 메모 (관리자만 읽기·쓰기)
admins/{email}                추가 관리자
auditLogs/{id}                변경 이력: uid, email, action, target, detail, at(서버 시각), subject(관리자 작업 대상 uid). ID 가 시간 역순이라 최신순 조회
meta/taxonomyTemplate         관리자가 편집한 추천 분류 템플릿
meta/appConfig                가입 승인제(approvalRequired), 전체 공지(notice)
```

환율은 [open.er-api.com](https://open.er-api.com) 에서 12시간 경과 시 자동 갱신됩니다 (설정에서 끌 수 있음).
